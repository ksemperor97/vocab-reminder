# 2026-09-08 완성도 개선 구현

사용자 요청: 평가에서 제안한 개선을 구현하고, Android/Mac 양쪽에서 추천이 보이지 않는 문제를 해결한다. 사용자 확인에 따라 내 단어 50개 제한을 폐지한다.

## 구현

- Android/Mac 추천 엔진과 스케줄러의 50개 진입 제한 제거. 빈 단어장에서는 기본 난이도로 시작한다.
- 학습 시작 전 추천만 대기 슬롯으로 계산한다. 학습을 시작한 추천은 일반 복습 우선순위에 포함하며 미래 복습일이 새 추천을 막지 않는다.
- Android는 잠자는 시간에도 목록을 준비하되 알림은 차단한다. 생성 뒤 UI를 다시 읽고 추천 탭 진입 때도 편성한다.
- Mac은 시작 시와 실행 중 1분마다 로컬 편성한다. 오늘 처리한 카드 수를 빼고 생성하며 네트워크 연결 없이도 동작한다.
- 추천 비활성, 목표 완료, 복습 우선, 대기 추천, 후보 소진을 구분해서 안내한다.
- 사용자 문맥의 주제 신호를 로컬에서 계산하고, 빈도·학습 난이도와 함께 추천에 반영한다. 서버로 문맥을 추가 전송하지 않는다.
- Mac 저장은 한 사용자 작업의 카드·후보·이벤트를 한 번에 기록한다. 실패 시 직전 저장 상태로 되돌리고 입력을 유지한다. 디스크 쓰기에 성공해야 알림·자동 동기화를 진행한다. 백업은 원본 파일을 옮기지 않고 원자적으로 복사한다.
- `primary_definition_candidate_id`를 저장/교환한다. 이전 클라이언트 데이터는 기존 뜻 내용을 기준으로 후보 ID를 복원한다.
- 제공자가 구조화된 복수 뜻을 반환하면 최대 20개를 보존하고 대안 뜻은 자동 선택하지 않는다. 실제 제공자의 뜻 정확성을 보증하는 기능은 아니다.
- `/sync/changes`에 인증, 트랜잭션 기반 변경 이력, 페이지 제한, 커서 초기화, 기존 `/sync/snapshot` 호환을 추가한다. 클라이언트는 서버가 `sync_protocol: 2`를 광고할 때 사용한다.
- 커서는 로컬 import 성공 후에만 저장한다. Mac은 데이터와 커서를 함께 저장하고, Android는 데이터 저장 뒤 커서를 저장해 중단 시 안전하게 재처리한다. 서버가 재시작하면 epoch를 바꿔 복구된 DB와 과거 커서의 혼동을 막는다.
- 업로드는 저장된 SHA-256 확인 이력과 비교해 새로 생기거나 바뀐 항목만 400개 단위로 전송한다. 서버가 건너뛴 항목이 있으면 확인 이력을 확정하지 않으며, 서버 재시작/복원으로 커서가 초기화되면 로컬 전체 데이터를 다시 대조한다.
- Android 카드/이력 UI를 `CardSummary.kt`로 분리한다.
- Node 22를 루트와 서버에 고정하고, 서버 테스트 시작 전에 실제 SQLite 메모리 DB를 열어 ABI를 확인한다.
- Android/Mac 설치 후보 버전을 0.3.0(build 3)으로 올린다.

## 검증 항목

- 최초 추천, 반복 생성 방지, 비활성 설정, 잠자는 시간, 다음 날 슬롯 회복.
- 저장 실패 후 입력·기존 파일 유지, 복습 카드와 이력의 동시 롤백, 재시도 성공.
- 다의어 보존 및 선택 후보 ID의 재실행 후 유지.
- 변경분 인증·페이지 순회·동일 쓰기·트랜잭션 롤백·커서 초기화.
- 12,000개 이력의 400개 페이지 조회, 이후 1개 변경만 조회.
- Mac 커서 저장/재시작 및 잘못된 페이지 거부, DST 봄/가을 경계.
- 기존 서버/Android/Mac 회귀와 보안/추천 파이프라인 검증.

## 남은 외부 인수와 데이터 작업

- 검수된 추천 데이터는 149개다. 1,095개 장기 공급 목표는 미달이다. 기존 1,000개 fill queue와 licensed-import/review 파이프라인을 사용하되, 사람 검수를 대신했다고 표시하거나 생성 데이터로 검수 수량을 부풀리지 않는다.
- 실제 다의어 10개 문맥 정확성 검수 및 재배포 가능한 장기 사전 snapshot 선정은 별도 인수다.
- 운영 endpoint에 인증 토큰을 보내는 진단은 자동 승인 검토가 차단했다. 사용자가 해당 주소 사용을 승인하기 전에는 운영 endpoint 검증/24시간 soak를 실행하지 않는다.
- 실제 Mac mini 재부팅, 실제 네트워크 5분 단절, 24시간 연속 운영, Android 신규 설치/기존 설치본 upgrade는 코드 테스트 통과와 별도로 기록한다.
- 빌드된 설치 후보와 실제 기기에 설치된 버전을 구분한다. 설치 완료로 기록하려면 실제 설치·버전·기본 추천 동작을 확인해야 한다.
