01한눈에 보기

서버가 정답을 정한다

카드 병합, 같은 단어 접기, 추천 선택처럼 기기마다 답이 달라지면 안 되는 일은 서버만 합니다.

기기는 오프라인에서도 완전하다

캡처·복습·알림은 네트워크 없이 동작하고, 바뀐 행은 outbox에 쌓였다가 연결되면 올라갑니다.

뜻과 진도는 따로 병합

폰에서 복습하고 Mac에서 뜻을 고쳐도 둘 다 남습니다. 삭제는 되살아나지 않습니다.

읽기는 쓰지 않는다

내려받기 요청은 서버 데이터를 바꾸지 않습니다. 추천은 업로드 직후와 타이머에서만 채워집니다.

02구성 요소

04복습 스케줄

Android와 Mac이 같은 규칙으로 다음 복습 시점을 계산합니다. 같은 시각에 알림이 몰리지 않도록 몇 분 단위로 흩뜨립니다.

new10분

저장 직후 첫 알림

learning1일

첫 외움

learning3일

두 번째

review7일

7일부터 복습 단계

review×2

14 → 28 → 56일

mastered90일

90일 + 최근 2번 연속 외움

잊음

재학습 상태로 바뀌고 뜻과 예문을 보여 준 뒤 20분 뒤 다시 묻습니다. 다시 외우면 이전 간격의 절반(1~7일)부터 이어갑니다.

나중에

진도는 그대로 두고 60분 뒤로 미룹니다. 같은 카드는 하루 2번까지 미룰 수 있습니다.

조용한 시간

기본 23:00~09:00에는 알림을 보내지 않고, 끝난 뒤 30분 무렵으로 옮깁니다.

05동기화 (프로토콜 3)

카드는 통째로 덮어쓰지 않습니다. 필드를 두 묶음으로 나누고 묶음마다 시계(버전 + 시각)를 두어, 더 새로운 쪽이 그 묶음만 가져갑니다. 나머지는 한 방향으로만 바뀝니다.

내용

content_version · content_updated_at
뜻영영 정의품사발음예문출처 앱·URL대표 뜻 후보

학습 상태

schedule_version · schedule_updated_at
상태다음 복습간격잊은 횟수잊기 전 간격

한 방향으로만

시계 없음
삭제: 가장 이른 시각, 되살아나지 않음추천 → 내 단어장 승격추천 시작 시각: 가장 이른 값

한 번의 동기화

  1. outbox에 쌓인 행만 POST /sync/batch로 올림 (비어 있어도 보냄: 서버가 추천을 채우는 계기)
  2. 서버가 병합하고 같은 단어를 접은 뒤, 추천을 채움
  3. GET /sync/changes?cursor=…로 바뀐 행만 내려받음
  4. 기기가 같은 규칙으로 병합해 저장하고, 서버가 받은 행을 outbox에서 지움
  5. 가져오기가 끝난 뒤에만 cursor를 저장 (중간에 끊겨도 다시 하면 그만)

같은 단어가 두 장 생기면

  1. 폰과 Mac이 동기화 전에 같은 단어를 각자 저장
  2. 서버가 같은 lemma의 활성 카드를 찾아 하나를 남김 (내 단어장 → 뜻 있음 → 먼저 저장 순)
  3. 남는 카드는 가장 멀리 간 학습 진도를 가져가고, 나머지는 merged_into가 붙은 삭제 카드가 됨
  4. 문맥·복습 기록은 남는 카드로 옮겨지고, 기기는 결과를 그대로 받음
요청하는 일쓰기 여부
POST /sync/batch카드·문맥·뜻 후보·복습 기록·추천 피드백·설정 업로드, 병합·접기·추천 채우기씀
GET /sync/changescursor 이후 바뀐 행 (400개씩, has_more)읽기만
GET /sync/snapshot전체 사본 (구버전 호환)읽기만
GET /dict/:lemma, POST /dict/batch사전 조회, 문장이 있으면 문맥 뜻 선택 (분당 횟수 제한, 캐시)읽기만
GET /health서버 상태와 카드 수읽기만

세 구현(JS·Kotlin·Swift)이 같은 규칙인지는 shared/test-vectors/card_merge.json의 8개 사례로 확인합니다.

06시나리오

사용자가 실제로 겪는 흐름입니다. 실제 실행 확인 표시는 서버, Android 에뮬레이터, Mac 저장소, Mac 앱 화면(XCUITest)을 실제로 돌리는 npm run e2e:real로 확인한 것이고, 테스트는 단위·통합 테스트로 고정한 것입니다.

캡처 · Android실제 실행 확인

기사 읽다가 단어 공유

  1. 브라우저에서 “resilient” 선택 → 공유 → Vocabulary Reminder
  2. 미리보기에서 뜻 “회복력 있는, 탄력 있는” 확인 후 저장
  3. 앱이 바로 동기화

결과 10분 뒤 첫 알림이 예약되고, Mac도 다음 동기화에 같은 카드를 받습니다.

캡처 · 공통테스트

문장을 통째로 공유

  1. “The results are tentative, but the pattern is robust.” 공유
  2. 단어 후보(tentative, robust …) 중 하나를 고름
  3. 고른 단어 + 원문 문장이 문맥으로 저장

결과 카드에 원문 문장과 출처 앱이 함께 남습니다.

캡처 · 공통실제 실행 확인

사전에 없는 단어

  1. “serendipity”처럼 기기 사전에 없는 단어를 저장
  2. “뜻 없음 · 알림 보류”로 일단 저장
  3. 서버 사전으로 백그라운드 보강, 실패하면 이유 표시

결과 캡처는 막히지 않고, 뜻이 생기면 그때 복습 알림이 시작됩니다.

캡처 · Mac테스트

Mac에서 단축키로 저장

  1. 아무 앱에서 단어 복사 후 ⌘⌥V (또는 서비스 메뉴 “Vocabulary Reminder에 추가”)
  2. 메뉴바 창에 macOS 사전 뜻이 뜸
  3. 저장하면 1초 뒤 자동 동기화

결과 폰에서도 몇 분 안에 같은 카드가 보입니다.

복습 · Android테스트

알림에서 바로 답하기

  1. 잠금 화면 알림 “resilient” → 외움 / 잊음 / 나중에
  2. 잊음이면 뜻과 예문을 보여 주는 알림으로 바뀜
  3. 20분 뒤 다시 확인

결과 앱을 열지 않고 복습이 끝나고, 기록은 다음 동기화 때 올라갑니다.

복습 · 워치테스트

Galaxy Fit3로 답장

  1. 폰 알림이 워치에 미러링
  2. 빠른 답장 “네·좋습니다” = 외움, “아니오” = 잊음, “나중에” = 미룸
  3. 뜻 알림은 아무 답장이나 하면 넘어감

결과 손목에서 복습을 이어갈 수 있습니다.

추천테스트

추천 단어 받기

  1. 오늘 목표에 여유가 있으면 서버가 추천 카드를 채움
  2. 알림·추천 단어장에서 시작하기 / 알아요 / 관심 없음
  3. 알아요·관심 없음은 다시 추천되지 않음

결과 고른 반응에 따라 다음 추천의 난이도와 주제가 조정됩니다.

복습 · 공통테스트

밤에는 조용히

  1. 23시 이후 복습할 카드가 생김
  2. 알림은 보내지 않고 대기
  3. 09:30 무렵 한 장씩 다시 시작

결과 잠자는 동안 알림이 오지 않고, 아침에 몰리지도 않습니다.

두 기기실제 실행 확인

지하철에서 복습, 집에서 뜻 수정

  1. 폰이 오프라인일 때 “resilient” 복습 → 외움
  2. 같은 시간에 Mac에서 뜻을 “(Mac 수정) 회복력 있는”으로 고침
  3. 폰이 다시 연결

결과 서버·폰·Mac 모두 Mac의 뜻 + 폰의 학습 상태(learning, 1일)를 가집니다.

두 기기실제 실행 확인

같은 단어를 두 곳에서 저장

  1. 폰이 오프라인일 때 “meticulous” 캡처
  2. Mac에서도 “meticulous”를 뜻과 함께 저장
  3. 폰이 연결되어 업로드

결과 카드는 한 장만 남고, 두 기기의 문맥이 모두 그 카드에 붙습니다.

두 기기실제 실행 확인

Mac에서 삭제

  1. Mac에서 카드 삭제 후 동기화
  2. 폰이 다음 동기화에서 삭제를 받음
  3. 오래된 사본이 다시 올라와도 무시

결과 폰 화면에서도 사라지고, 다시 살아나지 않습니다.

두 기기실제 실행 확인

오래 오프라인이었다가 연결

  1. 폰을 며칠 오프라인으로 사용하며 캡처·복습
  2. 연결되면 쌓인 행만 업로드
  3. 그사이 바뀐 서버 행만 내려받음

결과 전체를 다시 보내지 않고, 끝나면 outbox가 비어 있습니다.

두 기기 · Mac 앱 화면실제 실행 확인

Mac 창에서 저장, 폰에서 확인

  1. 메뉴바에서 앱을 열고 “ephemeral” 입력 → 미리보기
  2. 뜻을 “덧없는”으로 적고 저장 → “지금 동기화”
  3. 폰이 다음 동기화에서 받음

결과 폰 단어장에 ephemeral과 뜻 “덧없는”이 그대로 보입니다.

두 기기 · Mac 앱 화면실제 실행 확인

폰에서 캡처, Mac 창에서 확인

  1. 폰에서 “robust” 공유 캡처
  2. Mac 앱에서 “지금 동기화”
  3. 최근 저장 단어 목록 확인

결과 Mac 창에 robust가 “견고한, 안정적인”으로 나타납니다.

두 기기 · Mac 앱 화면실제 실행 확인

Mac 카드 편집기에서 뜻 수정

  1. Mac 사이드바에서 robust 선택 → 편집기
  2. 뜻을 “(Mac 앱) 튼튼한”으로 고치고 저장 → 동기화
  3. 폰이 다음 동기화에서 받음

결과 폰 화면에 새 뜻이 보이고, Mac 카드 기록에는 수정·뜻 후보·동기화가 남습니다.

설치·운영실제 실행 확인

앱 업데이트

  1. 예전 버전(SharedPreferences / vocab-data.json)이 설치된 상태에서 새 버전 설치
  2. 첫 실행 때 SQLite로 한 번 옮김
  3. 옮긴 데이터를 전부 한 번 다시 업로드

결과 단어와 기록이 그대로 남습니다. 서버 쪽은 같은 행을 받아도 결과가 같습니다.

설치·운영테스트

서버 DB를 백업에서 복구

  1. 서버 변경 로그가 새로 시작됨(epoch 변경)
  2. 기기는 다음 동기화에서 이를 알아챔
  3. 가진 행을 전부 다시 보내고 전체 사본을 받음

결과 복구 이후 기기에서 생긴 변경도 서버로 돌아옵니다.

설치·운영테스트

저장 중 실패

  1. 디스크 오류 등으로 저장 트랜잭션 실패
  2. 카드·기록·후보가 함께 되돌아감
  3. 입력하던 미리보기는 그대로 남음

결과 반쯤 저장된 상태가 생기지 않고, 다시 저장하면 됩니다.

07저장 구조

기기 (Android · Mac 공통)

cards카드 1장 = 1행, 본문은 동기화 JSON 그대로
contexts캡처 문맥(문장, 출처)
definition_candidates뜻 후보와 복원 기록
review_events복습 기록 (카드별 인덱스)
recommendation_feedback시작하기·알아요·관심 없음
outbox아직 서버가 받지 않은 행
kv설정, cursor 등

서버

cards 외 4개기기와 같은 엔티티, body_json + 비교용 열
sync_changes트리거가 쌓는 변경 로그 (cursor의 근거)
sync_metadataepoch (복구 감지)
settings사용자 설정 1행
문맥·후보·기록은 card_id 인덱스로 조회합니다. 백업은 매일, 30개 보관.
